# Session Objective Protocol

## 触发条件

发现阶段（扫描已有文件）始终执行，不受触发条件限制。触发条件仅控制是否**新建** objective。

只有以下场景才新建 objective：
- 任务涉及**两个及以上可识别的执行步骤**
- 或用户明确要求跟踪进度

**怎么判断"两个及以上执行步骤"**：每个步骤应有独立的、可验证的产出。例如：
- "改 schema → 改 API → 改前端"——三个步骤，每个有独立产出，应创建
- "写一个函数并加测试"——虽然是两件事，但产出紧密耦合、通常在一轮完成，不需要创建
- "查一个文件然后回答问题"——本质是单步查询，不需要创建

单步骤操作、纯问答、快速查询直接执行，不创建 objective。如果不确定，先正常执行；发现任务实际复杂度超出预期时，再回头创建。

## 发现与绑定

每次会话开始时，扫描 `.ai-objectives/` 目录下所有 `.md` 文件。如果目录不存在，跳过发现阶段，按触发条件决定是否创建。

1. **存在 `status: active` 的文件时**（无论当前任务是否简单，都应通知用户，避免遗忘进行中的工作）：
   - 读取每个文件的 frontmatter `objective` 和 `created` 字段
   - 如果只有一个 active 文件：向用户确认："发现一个进行中的目标：`<objective>`（创建于 `<created>`，文件：`<文件名>`），是否继续？"
   - 如果有多个 active 文件：列出所有文件的**文件名 + objective + created 时间**，让用户选择
   - 如果文件创建时间超过 7 天，额外提示可能已过时，询问是否归档
   - 用户确认后绑定该文件；用户否认后，询问是要新建、归档/清除、还是**暂时忽略**（不绑定任何 objective，按正常模式工作）
2. **不存在 active 文件时**：如果当前任务满足触发条件，进入创建流程

**绑定后不得切换**：如果用户对话方向明显偏离当前 objective，应提示用户而非静默切换。
