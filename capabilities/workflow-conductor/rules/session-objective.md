# Session Objective Protocol

## 触发条件

发现阶段（扫描已有文件）始终执行，不受触发条件限制。触发条件仅控制是否**新建** objective。

**硬触发**（无需判断，不适用"不确定时先执行"的宽限）：
- 用户明确要求跟踪进度（如"帮我维护目标"、"记录进度"、"建个 objective"等）→ 进入创建流程
- 用户要求记住某条要求或约束（如"记住这个"、"以后都要这样"、"这个很重要别忘了"等）→ 若已有 active objective，立即追加到关键约束列表；若无 active objective，先创建再追加

**条件触发**（需判断后决定）：
- 任务涉及**两个及以上可识别的执行步骤**（每个步骤有独立的、可验证的产出）

**怎么判断"两个及以上执行步骤"**：
- "改 schema → 改 API → 改前端"——三个步骤，每个有独立产出，应创建
- "写一个函数并加测试"——虽然是两件事，但产出紧密耦合、通常在一轮完成，不需要创建
- "查一个文件然后回答问题"——本质是单步查询，不需要创建

单步骤操作、纯问答、快速查询直接执行，不创建 objective。如果开始时无法判断步骤数，先执行第一步；**完成第一步后必须重新评估**：若剩余任务仍有两步及以上，立即暂停并创建 objective，再继续执行。

## 发现与绑定

每次会话开始时，扫描 `.ai-objectives/` 目录。存在 `status: active` 的文件时通知用户并绑定；不存在时按触发条件决定是否创建。目录不存在则跳过。

## 读取

- 绑定 objective 文件后，在每次回复前参考其中的进度和约束。文件中的核心目标、执行进度和关键约束优先于对话历史中的零散信息——对话可能被压缩或遗忘，文件不会
- 当需要查阅需求文档、PRD、标准规范、外部链接等参考素材时，首先查阅 objective 文件的「参考资料」段落——它是所有外部素材的索引入口，不要搜索对话历史或凭猜测行动
- 当约束列表中的内容与用户的即时指令冲突时，以用户即时指令为准，并更新约束列表以反映变化

## 按需加载

一旦绑定已有 objective 或决定新建 objective，**立即读取完整协议**：查找并读取 `conductor-protocol.md`（位于 `.cursor/references/`、项目 references 目录、或 `~/.claude/` 相关路径下）。完整协议包含创建流程、文件模板、更新规则、步骤间检查、禁止行为和执行原则等详细规定。**不得在未读取完整协议的情况下创建或操作 objective 文件。**
